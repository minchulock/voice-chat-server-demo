브라우저 음성 대화를 Spring Boot로 구현하는 방법

기존 Python 데모의 Browser → Mic → VAD → in-memory audio → HTTPS 흐름과, Browser ← sentence prefetch audio/SSE ← Speaker 흐름을 Java 개발자가 재구현할 수 있도록 정리한 실전 가이드입니다.

API Key는 서버에만오디오 파일 저장 없음문장 단위 TTS prefetch멀티턴 SessionBarge-in

1. 목표와 책임 분리

핵심은 브라우저를 음성 입출력 장치로, Spring Boot를 인증정보를 보관하는 API 프록시와 세션 오케스트레이터로 두는 것입니다.

Browser

마이크 권한, VAD, MediaRecorder, 메모리 Blob, 화면 상태, WAV 재생, SSE 해석, TTS 중 사용자 발화 감지를 담당합니다.

Spring Boot

API 키 보관, STT multipart 변환, Agent/Model 호출, 대화 이력, TTS 바이트 프록시, 입력 검증과 오류 표준화를 담당합니다.

중요: 브라우저에서 외부 CLOVA API를 직접 호출하지 않습니다. API 키는 application.yml의 환경변수 참조로만 서버에 보관합니다.

다음 문장 합성
  1. 세션 생성 후 브라우저가 마이크 스트림을 열고, AnalyserNode의 RMS 값으로 발화 시작과 종료를 판정합니다.
  2. MediaRecorder가 만든 조각은 배열에만 보관하며, 발화 종료 시 Blob으로 합쳐 Spring의 /api/stt에 raw body로 전송합니다.
  3. Spring은 메모리의 바이트를 multipart 파일 파트로 감싸 외부 STT API에 전달합니다. 디스크 저장은 필요 없습니다.
  4. 전사문을 Agent 또는 Model API에 보내 답변을 받고 세션 대화 이력을 갱신합니다.
  5. 브라우저가 답변을 문장으로 분리합니다. 첫 문장 TTS를 받고 재생하는 즉시 두 번째 문장 요청을 병렬로 시작합니다.
  6. 마지막 문장 재생이 끝나면 자동으로 다음 Turn VAD로 돌아갑니다. 재생 중 사용자 발화가 감지되면 TTS를 중단하고 바로 새 Turn을 녹음합니다.

STT — raw body를 메모리 multipart로 변환

@PostMapping(path = "/api/stt", consumes = MediaType.ALL_VALUE)
public Mono<Map<String, Object>> stt(
    @RequestBody Mono<DataBuffer> body,
    @RequestHeader(HttpHeaders.CONTENT_TYPE) String contentType,
    @RequestParam(defaultValue = "whisper-large-v3") String model,
    @RequestParam(defaultValue = "ko") String language) {

  long started = System.nanoTime();
  return DataBufferUtils.join(body)
      .flatMap(buffer -> {
        byte[] audio = new byte[buffer.readableByteCount()];
        buffer.read(audio);
        DataBufferUtils.release(buffer);
        if (audio.length < 32 || audio.length > 20 * 1024 * 1024) {
          return Mono.error(new ResponseStatusException(BAD_REQUEST, "오디오 크기 오류"));
        }
        return sttService.transcribe(audio, contentType, model, language);
      })
      .map(result -> Map.of(
          "transcript", result.transcript(),
          "model", result.model(),
          "processingMs", (System.nanoTime() - started) / 1_000_000));
}

public Mono<SttResult> transcribe(byte[] audio, String mime, String model, String language) {
  MultipartBodyBuilder form = new MultipartBodyBuilder();
  form.part("model", model);
  form.part("response_format", "json");
  if (!"auto".equals(language)) form.part("language", language);
  form.asyncPart("file", Mono.just(audio), byte[].class)
      .filename(extensionFor(mime)).contentType(MediaType.parseMediaType(mime));

  return webClient.post().uri(properties.sttUrl())
      .contentType(MediaType.MULTIPART_FORM_DATA)
      .body(BodyInserters.fromMultipartData(form.build()))
      .retrieve()
      .onStatus(HttpStatusCode::isError, this::upstreamError)
      .bodyToMono(SttResult.class);
}

TTS — 바이트를 버퍼링하지 않고 그대로 프록시

public record TtsRequest(
    @NotBlank String input,
    @NotBlank String model,
    @DecimalMin("0.5") @DecimalMax("2.0") double speed,
    @Pattern(regexp = "audio|sse") String stream_format) {}

@PostMapping("/api/tts")
public Mono<ResponseEntity<Flux<DataBuffer>>> tts(@Valid @RequestBody TtsRequest body) {
  return webClient.post().uri(properties.ttsUrl())
      .contentType(MediaType.APPLICATION_JSON)
      .bodyValue(body)
      .exchangeToMono(upstream -> {
        if (upstream.statusCode().isError()) {
          return upstream.bodyToMono(String.class)
              .flatMap(text -> Mono.error(new UpstreamException(text)));
        }
        MediaType type = upstream.headers().contentType()
            .orElse(body.stream_format().equals("sse")
                ? MediaType.TEXT_EVENT_STREAM : MediaType.parseMediaType("audio/wav"));
        return Mono.just(ResponseEntity.ok()
            .contentType(type)
            .header(HttpHeaders.CACHE_CONTROL, "no-store")
            .header("X-Accel-Buffering", "no")
            .body(upstream.bodyToFlux(DataBuffer.class)));
      });
}
왜 WebFlux인가? Flux<DataBuffer>를 사용하면 Spring이 전체 WAV 또는 SSE 응답을 메모리에 모은 뒤 반환하지 않고, 외부 API에서 도착한 청크를 브라우저로 연속 전달할 수 있습니다.

@PostMapping("/api/chat")
public Mono<ChatResponse> chat(@Valid @RequestBody ChatRequest request) {
  Conversation session = store.require(request.sessionId());
  Mono<String> answer = request.provider().equals("agent")
      ? chatService.callAgent(session, request)
      : chatService.callModel(session, request);
  long started = System.nanoTime();
  return answer.map(text -> {

    return new ChatResponse(text, turn, request.provider(),
        (System.nanoTime() - started) / 1_000_000);
  });
}

마이크 열기와 녹음

let stream, recorder, analyser, frame;
let chunks = [], heardVoice = false, lastVoiceAt = 0;
const threshold = 0.018, silenceMs = 1100;

async function startListening() {
  stream = await navigator.mediaDevices.getUserMedia({
    audio: { channelCount: 1, echoCancellation: true,
             noiseSuppression: true, autoGainControl: true }
  });
  const context = new AudioContext();
  const source = context.createMediaStreamSource(stream);
  analyser = context.createAnalyser();
  analyser.fftSize = 2048;
  source.connect(analyser);

  chunks = [];
  recorder = new MediaRecorder(stream, { mimeType: preferredMime() });
  recorder.ondataavailable = e => { if (e.data.size) chunks.push(e.data); };
  recorder.onstop = async () => {
    const audioBlob = new Blob(chunks, { type: recorder.mimeType });
    stopTracks();
    await runTurn(audioBlob);          // 디스크 저장 없이 Blob 전송
  };
  recorder.start(250);
  monitorVad(performance.now());
}

function preferredMime() {
  return ['audio/webm;codecs=opus', 'audio/mp4', 'audio/webm']
    .find(MediaRecorder.isTypeSupported.bind(MediaRecorder)) || '';
}

RMS 기반 VAD

function monitorVad(startedAt) {
  const values = new Uint8Array(analyser.fftSize);
  analyser.getByteTimeDomainData(values);
  let sum = 0;
  for (const value of values) {
    const sample = (value - 128) / 128;
    sum += sample * sample;
  }
  const rms = Math.sqrt(sum / values.length);
  const now = performance.now();
  if (rms > threshold) { heardVoice = true; lastVoiceAt = now; }
  if (heardVoice && now - lastVoiceAt > silenceMs) {
    recorder.stop();
    return;
  }
  if (now - startedAt > 20_000) { recorder.stop(); return; }
  frame = requestAnimationFrame(() => monitorVad(startedAt));
}

  });
  const response = await fetch(`/api/stt?${query}`, {

7. 문장 단위 TTS 선행 합성

전체 답변을 한 번에 TTS로 보내면 첫 음성까지 오래 기다립니다. 답변을 문장 단위로 나누고, 현재 문장을 재생하는 동안 다음 문장의 TTS 요청을 시작하면 문장 사이 공백을 줄일 수 있습니다.

function splitSentences(text, max = 120) {
  const sentences = [...new Intl.Segmenter('ko', { granularity: 'sentence' })
    .segment(text)].map(x => x.segment.trim()).filter(Boolean);
  return sentences.flatMap(sentence => {
    const parts = [];
    while (sentence.length > max) {
      parts.push(sentence.slice(0, max));
      sentence = sentence.slice(max);
    }
    if (sentence) parts.push(sentence);
    return parts;
  });
}

async function speakAnswer(answer, signal) {
  const sentences = splitSentences(answer);
  let prepared = requestTts(sentences[0], signal); // 첫 문장 즉시 합성

  for (let i = 0; i < sentences.length; i++) {
    const audioBlob = await prepared;
    prepared = i + 1 < sentences.length
      ? requestTts(sentences[i + 1], signal)       // 재생 전 다음 문장 선행 합성
      : null;
    const result = await playWithBargeIn(audioBlob, signal);
    if (result === 'interrupted') return result;
  }
  return 'ended';
}

async function requestTts(sentence, signal) {
  const response = await fetch('/api/tts', {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ input: sentence, model: 'melo-tts-ko',
      speed: 1.6, stream_format: 'audio' }), signal
  });
  if (!response.ok) throw new Error(await response.text());
  return response.blob();
}
주의: 이 방식의 “prefetch”는 문장 N을 재생하면서 문장 N+1의 완성된 WAV를 준비하는 방식입니다. WAV 컨테이너를 단순히 받은 청크마다 각각 재생하는 것은 아닙니다. 진짜 저지연 PCM 재생은 AudioWorklet과 raw PCM 포맷이 별도로 필요합니다.

8. Audio 스트림과 SSE 이벤트 스트림

옵션서버 응답브라우저 처리특징
audioaudio/wav 바이너리response.blob()구현이 가장 단순합니다. WAV는 메모리에 존재하며 파일 저장은 선택 사항입니다.
ssetext/event-streamdata 이벤트 JSON의 Base64 audio를 디코딩이벤트 메타데이터를 함께 보낼 수 있으나 Base64로 약 33% 커지고 파서가 필요합니다.
async function sseAudioBlob(response) {
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '', chunks = [];
  while (true) {
    const { value, done } = await reader.read();
    buffer += decoder.decode(value || new Uint8Array(), { stream: !done });
    const events = buffer.split(/\r?\n\r?\n/);
    buffer = events.pop() || '';
    for (const event of events) {
      for (const line of event.split(/\r?\n/)) {
        if (!line.startsWith('data:')) continue;
        const raw = line.slice(5).trim();
        if (!raw || raw === '[DONE]') continue;
        const json = JSON.parse(raw);
        if (json.audio) chunks.push(Uint8Array.from(atob(json.audio),
          c => c.charCodeAt(0)));
      }
    }
    if (done) break;
  }
  return new Blob(chunks, { type: 'audio/wav' });
}

선택 기준: 단순한 음성 대화 데모는 audio가 현실적입니다. API가 SSE만 제공하거나 진행 이벤트가 필요할 때 SSE를 사용하십시오. 두 방식 모두 브라우저 메모리에서 재생할 수 있으며 WAV 파일 저장은 필수가 아닙니다.

Barge-in — TTS 중 새 발화 감지

TTS 재생 전에 별도 마이크 감시를 먼저 준비합니다. 처음 약 250밀리초는 스피커 누설음을 기준 소음으로 학습하고, 동적 임계값을 160밀리초 이상 넘으면 오디오를 멈춘 뒤 같은 마이크 스트림을 새 Turn 녹음에 넘깁니다.

async function playWithBargeIn(blob, signal) {
  const monitor = await navigator.mediaDevices.getUserMedia({
    audio: { echoCancellation: true, noiseSuppression: true, autoGainControl: true }
  });
  const context = new AudioContext();
  await context.resume();
  const probe = context.createAnalyser();
  context.createMediaStreamSource(monitor).connect(probe);

  const url = URL.createObjectURL(blob);
  audio.src = url;
  await audio.play();
  const outcome = await raceAudioEndedAndSustainedVoice(audio, probe, 250, 160, signal);
  if (outcome === 'interrupted') {
    audio.pause();
    await startListening(monitor); // 준비된 스트림 재사용, 권한 재요청 지연 없음
  } else {
    monitor.getTracks().forEach(track => track.stop());
  }
  URL.revokeObjectURL(url);
  await context.close();
  return outcome;
}

Turn 상태 머신

LISTENING → STT → ANSWER → TTS → LISTENING
                   ↑        │
                   └────────┘  사용자 발화 인터럽트

종료 버튼:
generation 증가 → AbortController.abort() → MediaRecorder/track 정리
→ audio.pause() → Session DELETE → UI READY

비동기 콜백에는 현재 generation 값을 캡처해 둡니다. 세션 종료나 새 세션 생성 후 이전 요청이 늦게 도착해도 generation이 다르면 결과를 폐기해야 합니다.

10. HTTPS 배포와 완료 점검

Nginx 핵심 설정

location / {
  proxy_pass http://127.0.0.1:8080;
  proxy_http_version 1.1;
  proxy_buffering off;          # SSE/TTS 청크 지연 방지
  proxy_request_buffering off;  # 오디오 업로드 지연 최소화
  proxy_read_timeout 180s;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
  • 마이크 API는 localhost 또는 유효한 HTTPS에서만 사용합니다.
  • Permissions-Policy: microphone=(self)와 same-origin 정책을 적용합니다.
  • 브라우저에는 API 키, Authorization 헤더, 외부 API URL을 노출하지 않습니다.
  • STT body 크기, 질문 길이, model/slug 패턴, 세션 TTL을 제한합니다.
  • 외부 오류의 본문 전체나 API 키를 로그에 남기지 않습니다.
  • SSE 응답에는 Cache-Control: no-store와 X-Accel-Buffering: no를 설정합니다.
  • Chrome, Safari에서 마이크 권한 거부, 무음, 긴 발화, TTS 인터럽트, 세션 종료/재시작을 각각 테스트합니다.

권장 구현 순서

  1. 정적 HTML과 세션 API부터 구성합니다.
  2. raw 오디오 수신과 multipart STT를 연결합니다.
  3. Agent 또는 Model 중 하나를 먼저 연결한 뒤 세션 문맥을 추가합니다.
  4. TTS Audio 프록시를 먼저 완성하고, 필요할 때 SSE 파서를 추가합니다.
  5. 자동 다음 Turn, AbortController, Barge-in 순으로 상태 머신을 확장합니다.
  6. HTTPS와 Nginx buffering 해제를 적용하고 실제 브라우저에서 종단 테스트합니다.
